# Runbook: updating this ASUS CX54 (SCREEBO) safely
  > Power/sleep/hibernate background and the success criteria: entries/2026-11-09-power-sleep-hibernate-final-state.md

Written 2026-11-08 after the hibernate / S0ix / fingerprint work. Read the
2026-11-08 entries in entries/ for the why. Everything below is what an update
can touch and how to check it afterwards.

## A. System update (`sudo pacman -Syu`, incl. kernel and linux-firmware)

### What it affects
| Item | Effect of an update | Action |
|---|---|---|
| e820-hibfix (DKMS) | Rebuilt automatically for the new kernel | Check `dkms status` after the update |
| initramfs / UKIs | Regenerated by mkinitcpio (e820_hibfix module, no `kms`, ter-v32n font) | Nothing; check the build output had no errors |
| GSC firmware override `/usr/lib/firmware/updates/i915/mtl_gsc_1.bin` | Not package-owned → untouched; still loaded before linux-firmware's copy | Keep it until upstream ships ≥ r102.1.15.2024 |
| linux-firmware-intel (GuC/HuC/DMC/SOF/iwlwifi/IPU6) | New blobs | Watch for new errors after reboot |
| rust-fp-cros-local, fw-ectool-git | Local/AUR packages → not updated by -Syu | Rebuild only if a library they link against breaks |
| /etc drop-ins (logind, sleep, tmpfiles, modprobe, pam.d/sudo) | Kept (not package files) | pacman may write `*.pacnew` for pam.d/sudo or mkinitcpio.conf — merge, do not overwrite |
| Running kernel vs installed kernel | Mismatch until reboot | **Reboot before any hibernate** (S4 needs identical kernel + cmdline) |

### Procedure
1. No root snapshot is possible right now: the 32 GiB hibernate /swapfile lives
   in the root subvolume @. `btrfs subvolume snapshot` fails with "Text file busy";
   after `swapoff` the snapshot works but then `swapon` fails ("Invalid argument",
   extents shared with the snapshot) until the snapshot is deleted and
   `btrfs subvolume sync /` finishes (learned 2026-11-08). Fallbacks instead: the
   linux-lts UKI in the boot menu, and old packages in /var/cache/pacman/pkg
   (`pacman -U` to downgrade). Future fix: move the swapfile to its own subvolume
   (@swap) — changes resume_offset, needs cmdline + UKI rebuild + reboot.
2. Save work, close Brave (big upgrades can restart it).
3. `sudo pacman -Syu` — read the output for `.pacnew` files and mkinitcpio/DKMS errors.
4. `dkms status` → `e820-hibfix/1.2, <new kernel>: installed`.
5. Reboot (do not hibernate first).
6. Checks after reboot:
   - `journalctl -k -b0 | grep e820_hibfix` → loaded, `normalised eceee7ea` (same as before).
   - `journalctl -k -b0 | grep "Loaded GSC firmware"` → `r102.1.15.2024`.
   - `cat /sys/kernel/debug/pmc_core/package_cstate_show` (as root) → Package C10 > 0 at idle.
   - Fingerprint: `sudo -k; sudo true` → fingerprint prompt; lock screen unlock by finger.
   - Power button → session menu; lid close → suspend.
7. GPU driver is **xe** since 2026-11-08 (`/etc/modprobe.d/xe-driver.conf`). After a kernel
   update check: `lspci -k -s 00:02.0` → `driver in use: xe`; no new `xe 0000` errors in dmesg;
   `cat /sys/class/drm/card0/device/tile0/gt1/gtidle/idle_status` → gt-c6. The old i915 path
   `/sys/kernel/debug/dri/0000:00:02.0/gt1/drpc` does not exist under xe.
   If the kernel changed, hibernate once and re-check gt1 (gt-c6) + an s2idle S0ix test after it.
   Watch for `drm_WARN_ON_ONCE(ret == -110)` in mcr_lock (seen once, harmless so far).
   Lid + idle = suspend-then-hibernate after 24 h on battery (never on AC, HibernateOnACPower=no); image_size 4 GiB (tmpfiles).

### If something breaks
- Boot the other UKI (linux-lts) from the boot menu, or roll back with the snapshot.
- Resume falls back to a cold boot if e820-hibfix failed to load — safe, just no resume.
- sudo broken: log in as root over SSH from the Mac (`ssh asus-root`) and restore
  /root/hibfix-backup-20261108/pam.d-sudo.before-fingerprint.

## B. dots-hyprland: merging upstream end-4 (rewritten 2026-11-24)

`~/.dotfiles` is the fork: `origin` = github.com/l3ony2k/dots-hyprland-asus (PRIVATE),
`upstream` = end-4/dots-hyprland. The configs we edit are **symlinked** into it
(`asus/links.sh`), so the repo *is* the live config: merging upstream updates the running
desktop directly, and there is never anything to copy back.

**Never run** `./setup exp-update`, `exp-merge`, `install-files` or a plain `./setup install`:
they copy end-4's files over the symlinks (exp-update `rm -rf`s `~/.config/hypr` first). A guard
in `setup` refuses them while the links exist. Dependencies only: `./setup install --skip-allfiles`.

### 1. See what upstream changed (an agent can do this and summarise)
    cd ~/.dotfiles && git status            # must be clean: commit or stash first
    git fetch upstream
    git log --oneline HEAD..upstream/main          # new upstream commits
    git diff --stat HEAD...upstream/main           # files they touch
    git diff HEAD...upstream/main -- sdata/        # dependency / PKGBUILD changes
Summarise: fixes, features, which touched files we also changed
(`git diff --name-only $(git merge-base HEAD upstream/main) HEAD -- dots/` = our edited files).

### 2. Merge everything (not cherry-picks)
    git tag pre-merge-$(date +%Y%m%d)
    git merge upstream/main
Default is to take the whole upstream; don't hand-pick parts. Skipped upstream commits pile up
and every later merge gets harder. If an upstream change is unwanted, merge anyway and undo or
gate it (`Appearance.lok`) in a follow-up commit, so git records the decision. Exceptions: hold
the merge while upstream is mid-refactor; `git cherry-pick` a single urgent fix (the later full
merge recognises it). Conflicts: keep upstream's new logic, re-apply the lok styling on top.

### 3. Check (the shell reloads by itself; Hyprland: `hyprctl reload`)
- `~/.local/bin/ii-restart --check` prints nothing, then Ctrl+Super+R.
- `hyprctl configerrors` empty; `asus/links.sh status` all ok.
- lok rules for new upstream code: `grep -rn "border.width" ~/.config/quickshell/ii --include=*.qml | grep -v "lok\|LokFrame\|: 0"`
  (in lok they must be `LokFrame`; Qt's border drops sides at the 1.333 scale); new `layer.enabled`
  gated with `!Appearance.lok`; new long-running `Process` commands wrapped in
  `setpriv --pdeathsig TERM` (check `ps -eo ppid,cmd | awk '$1==1' | grep -E "nmcli|gdbus|inhibit|cava"` after two restarts).
- Keybinds: `custom/keybinds.lua` unbinds the dots' `SUPER + SUPER_L/R` (search is Super+Space)
  and `CTRL + SUPER + R` (→ `ii-restart`) by name; if upstream renamed those binds, both fire.
- If `sdata/` changed: `./setup install --skip-allfiles` (deps + services only).
- Screenshot the bar, sidebars, a popup in dark and light.
- Broken and no quick fix: `git reset --hard pre-merge-<date>` (Quickshell reloads the old tree).

### 4. Publish
    git push origin main
(Rebase + force-push is no longer used: merge commits keep the history of what we decided.)

### When you change a config
- Symlinked file (anything `asus/links.sh status` lists): just edit it, then `git commit` in ~/.dotfiles.
- Program-written file (`asus/home-sync.sh` MANIFEST): `asus/home-sync.sh pull`, review, commit.
- System file: copy into `asus/system/` (`asus/system-diff.sh pull` refreshes tracked ones), commit.
- Always also write an ops-log entry (`~/.local/share/claude/asus-arch-ops/`).

### Upstream changes that touch our custom behaviour (watch when merging)
- Overview.qml: F4 (XF86LaunchA) = full overview; search = Super+Space (2026-11-20).
- hyprland/general.lua: local `scale = 1.25` (custom/general.lua overrides the monitor anyway).
- lock/pam/fprintd.conf: rust-fp PAM line (see fingerprint entry).
- sdata/dist-arch/illogical-impulse-fonts-themes/PKGBUILD: `fish` removed from depends (pkgrel bumped).
  If upstream bumps it, keep fish out, rebuild with makepkg and `pacman -U`. fish is not installed;
  ii's update/change-password commands (config.json) and custom/variables.lua fallbacks use zsh.
- regionSelector: the lok colour loupe is a separate `LokColorLoupe.qml`; `CursorGuide.qml` is upstream.

## C. Login screen sessions (greetd / tuigreet, set up 2026-11-16)

tuigreet shows only the links in `/etc/greetd/sessions/` (`--sessions /etc/greetd/sessions`
in `/etc/greetd/config.toml`), so package-shipped entries such as `hyprland-uwsm.desktop`
(uwsm is not installed, the entry cannot start) stay hidden. Copies: `system/etc/greetd/`.

- New desktop installed and it should appear at login:
  `sudo ln -s /usr/share/wayland-sessions/<name>.desktop /etc/greetd/sessions/`
- Remove one: delete its link. Links follow package updates; a removed package's link just drops out.
- Takes effect the next time the login screen shows. Never restart greetd from inside a session.
- Details: `/etc/greetd/README-sessions.md`.
